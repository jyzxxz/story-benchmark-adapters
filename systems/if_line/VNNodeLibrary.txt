视觉小说编辑器 AI 节点库
========================

用途
----
这个文件整理当前项目中可创建的 VN 剧情流节点。

源码依据
--------
- 节点基类与枚举：Scripts/Logic/VNNode/VNNodeBase.cs
- 流程节点：Scripts/Logic/VNNode/Progress
- 动作节点：Scripts/Logic/VNNode/Action
- 自动保存/加载字段：Scripts/Logic/VNNode/Auto/*_Auto.cs
- 图保存结构：Scripts/Logic/VNNode/Save/VNGraphSaveData.cs
- 当前示例图：VNGraphs/vn_graph.json


一、剧情流 JSON 总结构
---------------------
根对象：

{
  "Version": 1,
  "StartNodeIndex": 1,
  "Nodes": [
    {
      "Index": 1,
      "DisplayName": "开始",
      "Comment": "",
      "NodeType": 1,
      "SubType": 6,
      "X": 80,
      "Y": 120,
      "Data": {},
      "Outputs": {
        "Next": [10]
      }
    }
  ]
}

节点公共字段：
- Index：int，节点唯一 ID。StartNodeIndex 必须指向一个开始节点。
- DisplayName：string，编辑器显示名，可为空；建议 AI 填一个剧情语义名。
- Comment：string，备注，可为空。
- NodeType：int，节点大类。Progress=1，Action=2。
- SubType：int，节点子类型。见下文枚举表。
- X / Y：float，编辑器画布位置，不影响运行。建议主线按 X 递增排布，动作节点放在对应流程节点下方。
- Data：Dictionary<string, VNSerializedValue>，节点参数。
- Outputs：Dictionary<string, List<int>>，输出端口到目标节点 Index 的连接。即使端口只能连 1 个节点，也要写成数组。

连接规则：
- Progress 节点组成剧情主流程，通常通过 `Next` 或 `Options[i].Next` 连接到 Progress 节点。
- Action 节点不直接进入主流程，通常被 Progress 节点的 `Actions`/`段落演出`/`同步演出` 输出引用。
- ActionSequenceNode 的 `Actions` 顺序就是执行顺序。
- ActionParallelNode 的 `Actions` 会同时执行。
- 输出端口容量为 0 表示无限连接；容量为 1 表示最多连接 1 个节点。


二、序列化值 VNSerializedValue
-----------------------------
Data 里的每个值都要用 `Kind` 包一层。当前示例文件使用的是简写形式，只写与该 Kind 有关的字段；未写字段反序列化时会走默认值。

String：
{"Kind":"String","StringValue":"文本"}

Int：
{"Kind":"Int","NumberValue":3}

Float：
{"Kind":"Float","NumberValue":0.5}

Double：
{"Kind":"Double","NumberValue":0.5}

Bool：
{"Kind":"Bool","BoolValue":true}

Enum：
{"Kind":"Enum","StringValue":"FadeIn"}

Vector2：
{"Kind":"Vector2","X":520,"Y":120}

Vector3：
{"Kind":"Vector3","X":0,"Y":0,"Z":0}

Color：
{"Kind":"Color","X":0,"Y":0,"Z":0,"W":1}

List：
{"Kind":"List","Items":[ ... ]}

Object：
{"Kind":"Object","ObjectValue":{ ... }}

Null：
{"Kind":"Null"}


三、基础枚举
-----------
VNNodeType：
- None = 0
- Progress = 1
- Action = 2

- Dialogue = 1，对话节点，可创建

- Chapter = 3，枚举存在，但当前没有对应可创建节点类
- Transition = 4，转场节点，可创建
- Choice = 5，选择节点，可创建
- Start = 6，开始节点，可创建

ActionNodeType：
- Tachi = 1，立绘入场，可创建
- SE = 2，枚举存在，但当前没有对应可创建节点类
- BackGround = 3，背景，可创建
- CV = 4，配音，可创建
- Audio = 5，音效，可创建
- Art = 6，插画，可创建
- Sequence = 7，顺序动作，可创建
- Parallel = 8，并行动作，可创建
- Delay = 9，等待，可创建
- Transition = 10，旧版动作转场枚举；当前转场是 Progress 节点
- TachiMove = 11，立绘移动，可创建
- TachiScale = 12，立绘缩放，可创建
- TachiExit = 13，立绘退场，可创建
- TachiMoveX = 14，水平移动，可创建
- TachiMoveBeside = 15，移动到旁边，可创建
- TachiEffect = 16，立绘效果，可创建
- MemoryEffect = 17，回忆泛黄，可创建
- BlinkEffect = 18，眨眼，可创建
- BlurEffect = 19，屏幕模糊，可创建
- ClearScreenEffect = 20，清除屏幕特效，可创建
- BackgroundMusic = 21，背景音乐，可创建

- FadeIn = 1

四、流程节点 Progress
--------------------

1. StartNode / 开始
- 菜单路径：流程/开始/开始
- NodeType：Progress = 1
- SubType：Start = 6
- 输入：无
- Data：{}
- Outputs：
  - Next：Progress，容量 1，下一剧情节点
- 说明：剧情入口。每张图至少需要一个 StartNode，并由 StartNodeIndex 指向它。

示例：
{
  "Index": 1,
  "DisplayName": "开始",
  "Comment": "",
  "NodeType": 1,
  "SubType": 6,
  "X": 80,
  "Y": 120,
  "Data": {},
  "Outputs": {"Next":[10]}
}


2. DialogueNode / 对话
- 菜单路径：流程/剧情/对话
- NodeType：Progress = 1
- SubType：Dialogue = 1
- 输入：Progress，容量 1
- Data：
  - SpeakerIdData：String，说话角色
  - TextData：String，台词内容
  - VoiceIdData：String，语音资源路径，可为空
- Outputs：
  - Actions：Action，容量 0，播放台词时同步执行的演出
  - Next：Progress，容量 1，下一剧情节点
- 说明：适合单句对白。先执行 Actions，同时显示 Line。

示例 Data：
"Data": {
  "SpeakerIdData": {"Kind":"String","StringValue":"荆轲"},
  "TextData": {"Kind":"String","StringValue":"风萧萧兮易水寒。"},
  "VoiceIdData": {"Kind":"String","StringValue":""}
}


3. ParagraphNode / 段落
- 菜单路径：流程/剧情/段落
- NodeType：Progress = 1
- SubType：Paragraph = 2
- 输入：Progress，容量 1
- Data：
  - Lines：List<DialogueLine>，对白列表
- DialogueLine 对象字段：
  - SpeakerId：String，说话角色
  - Text：String，台词内容
  - VoiceId：String，语音资源路径，可为空
- Outputs：
  - Actions：Action，容量 0，段落开头执行的演出
  - Next：Progress，容量 1，下一剧情节点
- 说明：适合一段连续对白。段落演出完成后显示第一句，玩家继续时在节点内部推进到下一句。

示例 Data：
"Data": {
  "Lines": {
    "Kind":"List",
    "Items":[
      {
        "Kind":"Object",
        "ObjectValue":{
          "SpeakerId":{"Kind":"String","StringValue":"旁白"},
          "Text":{"Kind":"String","StringValue":"夜色压在燕宫的铜灯上。"},
          "VoiceId":{"Kind":"String","StringValue":""}
        }
      },
      {
        "Kind":"Object",
        "ObjectValue":{
          "SpeakerId":{"Kind":"String","StringValue":"太子丹"},
          "Text":{"Kind":"String","StringValue":"秦兵不会等我们。"},
          "VoiceId":{"Kind":"String","StringValue":""}
        }
      }
    ]
  }
}


4. ChoiceNode / 选择
- 菜单路径：流程/剧情/选择
- NodeType：Progress = 1
- SubType：Choice = 5
- 输入：Progress，容量 1
- Data：
  - Options：List<ChoiceOption>，选项列表，最少 1 个，最多 6 个
- ChoiceOption 对象字段：
  - Text：String，选项文本
- Outputs：
  - Options[0].Next：Progress，容量 1，第 1 个选项的下一节点
  - Options[1].Next：Progress，容量 1，第 2 个选项的下一节点
  - 依此类推，最多 Options[5].Next
- 说明：选择完成后根据玩家选择跳到对应 Next。

示例：
"Data": {
  "Options": {
    "Kind":"List",
    "Items":[
      {"Kind":"Object","ObjectValue":{"Text":{"Kind":"String","StringValue":"询问太子丹的真正目的"}}},
      {"Kind":"Object","ObjectValue":{"Text":{"Kind":"String","StringValue":"先安抚樊於期"}}}
    ]
  }
},
"Outputs": {
  "Options[0].Next":[26],
  "Options[1].Next":[27]
}


5. TransitionNode / 转场
- 菜单路径：流程/画面/转场
- NodeType：Progress = 1
- SubType：Transition = 4
- 输入：Progress，容量 0，多输入
- Data：
  - TransitionType：Enum<VNTransitionType>，默认 FadeIn
  - BackgroundImage：String，背景资源路径，可为空
  - Color：Color，转场颜色，默认黑色
  - Duration：Float，持续时间，默认 0.45
- Outputs：
  - Next：Progress，容量 1，下一剧情节点
- 说明：转场时会清除所有立绘；如果 BackgroundImage 非空，会在转场中切换背景。

示例 Data：
"Data": {
  "TransitionType": {"Kind":"Enum","StringValue":"FadeOut"},
  "BackgroundImage": {"Kind":"String","StringValue":"res://Resources/JingKeStory/Backgrounds/yishui_river.png"},
  "Color": {"Kind":"Color","X":0,"Y":0,"Z":0,"W":1},
  "Duration": {"Kind":"Float","NumberValue":0.55}
}


五、动作节点 Action
------------------

1. ActionDelayNode / 等待
- 菜单路径：动作/控制/等待
- NodeType：Action = 2
- SubType：Delay = 9
- 输入：Action，容量 1
- Data：
  - Duration：Float，等待时间，默认 0.3
- Outputs：{}
- 说明：等待指定秒数后完成。常用于 Sequence 中控制节奏。


2. ActionSequenceNode / 顺序动作
- 菜单路径：动作/控制/顺序动作
- NodeType：Action = 2
- SubType：Sequence = 7
- 输入：Action，容量 1
- Data：{}
- Outputs：
  - Actions：Action，容量 0，按列表顺序依次执行
- 说明：当 Progress 节点需要一串演出按顺序发生时，用这个节点包起来。

示例 Outputs：
"Outputs": {"Actions":[101,102,103]}


3. ActionParallelNode / 并行动作
- 菜单路径：动作/控制/并行动作
- NodeType：Action = 2
- SubType：Parallel = 8
- 输入：Action，容量 1
- Data：{}
- Outputs：
  - Actions：Action，容量 0，同时执行
- 说明：需要多个演出同步进行时使用，例如两个立绘同时入场。


4. BackGroundNode / 背景
- 菜单路径：动作/画面/背景
- NodeType：Action = 2
- SubType：BackGround = 3
- 输入：Action，容量 1
- Data：
  - BackgroundImage：String，背景资源路径
  - ChangeType：Enum<BackgroundChangeType>，默认 FadeIn
  - Duration：Float，持续时间，默认 0.5
- Outputs：{}
- 说明：切换背景图。BackgroundImage 为空时仍会触发背景切换逻辑。


5. IllustrationNode / 插画
- 菜单路径：动作/画面/插画
- NodeType：Action = 2
- SubType：Art = 6
- 输入：Action，容量 0，多输入
- Data：
  - IllustrationImage：String，插画资源路径；为空表示清除插画
  - ChangeType：Enum<BackgroundChangeType>，默认 FadeIn
  - Duration：Float，持续时间，默认 0.5
- Outputs：{}
- 说明：显示插画并清空立绘。常用于 CG、关键场面。清除插画时 IllustrationImage 写空字符串。


6. TachiNode / 立绘入场
- 菜单路径：动作/立绘/立绘入场
- NodeType：Action = 2
- SubType：Tachi = 1
- 输入：Action，容量 1
- Data：
  - TachiID：String，立绘逻辑 ID，例如 jing_ke
  - TachiIamge：String，立绘资源路径。注意源码字段拼写是 TachiIamge，不是 TachiImage
  - TargetPosition：Vector2，目标位置
  - EnterType：Enum<TachiEnterType>，默认 FadeIn
  - Duration：Float，出场时间，默认 0.3
- Outputs：{}
- 说明：创建/显示一个立绘。后续移动、缩放、退场、效果都通过同一个 TachiID 操作。

示例 Data：
"Data": {
  "TachiID": {"Kind":"String","StringValue":"jing_ke"},
  "TachiIamge": {"Kind":"String","StringValue":"res://Resources/JingKeStory/Tachi/jing_ke.png"},
  "TargetPosition": {"Kind":"Vector2","X":520,"Y":120},
  "EnterType": {"Kind":"Enum","StringValue":"SlideInLeft"},
  "Duration": {"Kind":"Float","NumberValue":0.45}
}

六、推荐 AI 输出规范
-------------------
给 AI 配剧情流时，可以要求它遵守：

1. 只使用本文件标记为“可创建”的节点类型。
2. NodeType 和 SubType 使用数字，不要写枚举字符串。
3. Data 中的枚举值使用字符串名，例如 `"FadeOut"`、`"SlideInLeft"`。
4. 每个 Progress 主流程节点尽量有 Next，除非它是结尾或 Choice 分支。
5. ChoiceNode 必须让 `Options` 数组长度与 `Outputs` 中的 `Options[i].Next` 对应。
6. 立绘相关节点必须先通过 TachiNode 入场，再移动、缩放、退场或加效果。
7. 同一角色的 TachiID 保持稳定，例如 jing_ke、prince_dan、king_qin。
8. 动作节点本身不进入 Progress 主链，应由 `Actions` 输出引用。
9. Sequence 的 Actions 有顺序语义；Parallel 的 Actions 是同时执行。
10. 资源路径使用 Godot `res://` 路径。

常用画布位置建议：
- 主流程节点：X 每次增加 350 到 400，Y 约 80 到 160。
- 动作组节点：放在对应流程节点下方，Y 约 430。
- 具体动作节点：放在动作组下方，Y 每次增加 170 到 190。
