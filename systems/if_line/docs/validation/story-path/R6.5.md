# R6.5 Validation - Atomic Publication Workflow

## Scope

- Replaced the legacy draft, visibility, and multi-step release controls with
  one publication manager shared by the project list and StoryPath workbench.
- The only publish command is `POST /projects/{project_id}/publish`. It freezes
  the currently reviewed authoring Heads into a new immutable Release.
- The manager displays publication readiness, the authoring fingerprint,
  blocking items, the active Release, release notes, and Release history.
- Unpublish remains an explicit command and uses the latest publication
  `lock_version` as its `If-Match` precondition.

## Publication State

Authoring and publication are rendered as independent projections:

| Active Release | Current fingerprint matches | UI state | Public behavior |
| --- | --- | --- | --- |
| No | N/A | `unpublished` | No public Release is readable |
| Yes | Yes | `published` | The active Release remains readable |
| Yes | No | `changes_pending` | The old active Release remains readable until the next publish succeeds |

The owner project list no longer derives publication from `visibility` or
`is_draft`. It shows the authoring stage and publication state separately and
routes every publication action to the same manager.

## Atomic Publish

- The publish button is enabled only when readiness passes, reviewed authoring
  changes exist, and no authoring or publication command is running.
- The request carries `expected_authoring_fingerprint`, so a concurrent Head
  change cannot silently publish a different snapshot.
- A publish attempt receives one idempotency key scoped to the project,
  fingerprint, and release notes. An ambiguous network retry reuses that key;
  a definitive HTTP response or changed command receives a new key.
- A successful replacement makes the new Release active and leaves the prior
  Release visible in history as `superseded`.
- Publish and unpublish controls cannot run concurrently in the panel.

## Public Read Boundary

The public catalog is loaded from `/public/projects`. Selecting a work opens the
immutable active Release manifest from
`/public/releases/{release_id}/manifest`; it does not route an anonymous reader
through the mutable owner workbench. A complete reader over the release-scoped
chapter and VNGraph endpoints remains part of R8.5 end-to-end validation.
