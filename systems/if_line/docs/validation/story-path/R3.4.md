# R3.4 Validation - Multi-Path Isolation And Idempotency

## Scope

- Added an end-to-end sibling-path test that promotes two candidates from one
  reviewed CandidateSet, verifies distinct child placement identities and
  StateSnapshots, creates independent post-fork ChapterSlots, and changes one
  sibling's Chapter Head without moving the other sibling or root path.
- Added a repeated-branch test that creates a reviewed chapter on a child path,
  generates and activates a CandidateSet at that child checkpoint, promotes a
  candidate into a grandchild path, and verifies the exact three-chapter shared
  prefix, two-level parent lineage, cumulative StateSnapshot, and frozen
  branch-choice context for the next chapter.
- Added a durable idempotency test that commits a promotion and replays it from
  a new database session. The same command key and a second key for the same
  candidate both resolve to the original child path without duplicating it.
- Refactored test helpers to execute CandidateSet generation on any StoryPath
  and to build reviewable outlines and chapter revisions through the real
  application services. The tests do not bypass production validation by
  constructing target CandidateSet or child-path rows directly.

## Coupling Audit

- **Path topology:** each child owns its StoryPathChapter placement chain. Only
  immutable pre-fork ChapterSlots and selected ChapterRevisions are shared.
- **Sibling isolation:** post-fork slots differ, Head compare-and-swap targets a
  path-local placement UUID, and state resolves from each path's own base
  snapshot. No lookup identifies a branch by display order.
- **Repeated branching:** a child path can be a normal candidate-generation
  source. Its reviewed ChapterRevision and CandidateSet Head become the exact
  provenance of the grandchild; ancestry is not flattened back to the root.
- **Context:** the first fork choice is frozen into the child ChapterRevision
  context. The grandchild's next chapter sees that exact revision in its
  predecessor chain and its own second fork choice as the final prior-story
  item.
- **Idempotency:** StoryPathPromotionRecord survives commit boundaries. Exact
  replay does not write another record, while a new key for an already-promoted
  candidate records the command but resolves to the unique existing path.
- **Legacy reading:** the existing Release BranchEdge workflow remains covered
  by its regression suite and is not used to represent authoring StoryPaths.
- **Chapter index:** test setup populates the legacy bridge column and provider
  presentation metadata only. All tested ownership, traversal, and Head
  operations use UUID relations.
