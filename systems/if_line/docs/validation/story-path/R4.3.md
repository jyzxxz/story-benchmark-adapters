# R4.3 Validation - Immutable VNGraph Resource Manifest

## Scope

- Added immutable, content-addressed `VoiceLineVersion` snapshots. Editable
  `VoiceLine` rows remain TTS work records; every graph compile references the
  exact line payload and exact audio `AssetVersion` that existed at enqueue.
- Replaced duplicated mutable task inputs with one canonical binding manifest
  containing the exact ChapterRevision, ChapterScriptRevision, AssetVersion,
  StorageObject, VoiceLineVersion, audio AssetVersion, and compiler policy
  versions consumed by the graph.
- Made the worker verify task references, ownership, hashes, relational fields,
  and every immutable resource row before reconstructing compile input.
- Persisted the complete manifest and `binding_manifest_hash` on every
  `VNGraphRevision`. Deterministic compiles are unique by Script revision,
  manifest hash, compiler version, and schema version.
- Made AssetVersion, VoiceLineVersion, and VNGraphRevision reject ORM updates
  and deletes. Direct database tampering is detected by worker hash validation.
- Extended visual-asset graph children from the parent manifest with exact
  patch AssetVersions and derivation hashes. Parent manifest corruption and
  cross-project Asset or StorageObject references fail closed.
- Added migration `0033_immutable_vn_graph_manifest`, including exact online
  hashes, PostgreSQL offline DDL, reversible schema changes, and explicit
  legacy graph manifests.

## Coupling Audit

- **Chapter and Script:** immutable UUIDs and content hashes identify the graph
  source; chapter index remains presentation metadata only.
- **Assets and storage:** every consumed media reference includes exact
  AssetVersion and StorageObject hashes and is checked against project
  ownership, storage state, and deletion state.
- **Voice:** a task consumes VoiceLineVersion rows, never mutable VoiceLine
  values. Audio is frozen as an AssetVersion inside the line snapshot.
- **Tasks and workers:** one manifest is stored once, hashed once, and rebuilt
  without resolving current slots, bindings, lines, or Heads.
- **VNGraph history:** successful compile persists a ready immutable revision
  but does not move the review Head. Replays deduplicate only on the full
  deterministic compile tuple.
- **Visual edits:** graph children preserve parent resources and append exact
  patch versions with parent, patch, and result hashes.
- **Release and migration:** legacy graphs remain readable under an explicitly
  marked legacy manifest; release pinning continues to validate graph hashes.
- **Next item:** R4.4 removes the remaining index-based VNGraph assembly path.
