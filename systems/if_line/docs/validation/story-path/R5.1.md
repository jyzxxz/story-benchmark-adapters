# R5.1 Validation - Immutable Publication Fingerprint

## Scope

- Added a read-only publication readiness calculator independent from the
  legacy index-based Release builder.
- Canonicalized publication-relevant project metadata and all reviewed UUID
  Heads reachable through active StoryPaths.
- Excluded lock versions, timestamps, unselected Revisions, and archived path
  subtrees from the fingerprint.
- Added deterministic blocking items for missing Heads, invalid topology,
  stale provenance, corrupt immutable hashes, unbound resources, stale
  VoiceLines, and unavailable StorageObjects.
- Supported child paths with their own Outline Head and a shared immutable
  prefix from the parent path.
- Accepted Outline hashes created before activation filled generated
  `story_path_chapter_id` values, while still validating each row and the
  aggregate immutable hash.

## Coupling Audit

- **Project and Bible:** the calculator reads publication-relevant metadata and
  the exact ProjectContentHead Bible pointer; legacy visibility fields are not
  fingerprint inputs.
- **StoryPath and Outline:** only paths reachable through active ancestors are
  included. Every included path has an independent Outline Head and exact
  PathChapter topology.
- **Chapter and context:** each PathChapter resolves one exact ChapterRevision;
  inherited rows may resolve a frozen ancestor-path context but never an
  index-based chapter lookup.
- **Script and VNGraph:** Heads are keyed by ChapterRevision UUID and
  ScriptRevision UUID. The selected graph must pin the exact Script and Chapter
  hashes.
- **Assets and voice:** current ScriptResourceSlots and mutable VoiceLines must
  still match the selected graph's immutable AssetVersion and VoiceLineVersion
  manifest. Storage must remain active and non-deleted.
- **Release:** no ProjectRelease or ProjectPublication row is read, created, or
  changed. R5.2 consumes this snapshot inside the atomic publish transaction.
- **API:** no route is registered in R5.1. R6 exposes the already frozen
  `PublicationReadiness` response contract.
