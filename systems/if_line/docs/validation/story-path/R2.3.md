# R2.3 Validation - StoryPath Outline Generation

## Scope

- Removed the backend `pace -> 8/13/20` chapter-count mapping.
- Added one shared `chapter_count` policy with the accepted range `1..500`.
- Froze StoryPath, Bible Revision, parent Outline Revision, active PathChapter
  bindings, pace guidance, instructions, and requested count before provider calls.
- Persisted generated Outline Revisions as `ready` and unselected.
- Added explicit StoryPath Outline activation with transactional PathChapter
  reconciliation, stable UUID retention, reorder support, predecessor rebuilding,
  and new ChapterSlot allocation.
- Kept detached, unwritten PathChapters addressable and reusable. Activation
  rejects silent detachment when a ChapterSlot already has any ChapterRevision.
- Kept `chapter_index` only at the provider and rollback-bridge boundaries. The
  new Outline service performs no artifact identity lookup by chapter index.

## Focused Tests

Command:

```bash
cd backend
pytest -q tests/test_story_path_outline_service.py
```

Result: `18 passed`.

Coverage includes:

- arbitrary requested counts, including 7, 37, and the contract maximum 500;
- exact provider output count and contiguous numbering validation;
- count independence from `pace` in the prompt;
- frozen-source hash validation before any provider call;
- generation against an exact Bible Revision while mutable Heads change;
- generated Revision review state without Outline Head or PathChapter mutation;
- stable PathChapter IDs across activation, reorder, expansion, shrink, and
  reattachment;
- refusal to remove a chapter whose slot has a ChapterRevision;
- rejection of cross-StoryPath PathChapter references.

## Full-Suite Collection Limitation

`pytest --collect-only -q` collected 1076 tests but stopped with 13 existing
environment errors. The current interpreter does not have `redis`, `celery`,
`prometheus_client`, or `python-multipart`; affected modules fail during import
before tests run. No R2.3 module introduced those dependencies.

## Coupling Audit

- Backend active code no longer contains the `fast=8 / medium=13 / slow=20`
  mapping. The old generated `Docs/learn` snapshot remains historical only.
- The legacy frontend still displays approximate pace/count labels. Its removal
  and the new explicit count control belong to the R6.3/R6.4 frontend cutover.
- `story_generation_service.py` still contains the legacy
  `ChapterHead.chapter_index < target` query in chapter generation. R2.4 owns
  its replacement with `StoryContextResolver`; it is not used by the new
  Outline service.
- New StoryPath HTTP routes remain assigned to R6.1. R2.3 provides the complete
  application and task services those routes will call.
