# R5.2 Validation - Atomic Single-Step Publication

## Scope

- Added `publish_project` as the target write service; it does not call the
  legacy index-based Release builder or create a draft/prepared Release.
- Locked or transactionally created the sole ProjectPublication row before
  evaluating publication state.
- Compared the caller's expected fingerprint, locked all mutable source rows
  represented by the ready snapshot, and compared the fingerprint again before
  inserting a Release.
- Built `story-path-release-v1` manifests from UUID-keyed paths and chapters,
  embedding each selected VNGraph binding manifest and a sorted set of exact
  StorageObject IDs.
- Created a `published` ProjectRelease and moved
  `ProjectPublication.active_release_id` in one nested transaction. Failures
  leave neither a Release nor an empty ProjectPublication row.
- Kept legacy `Project.visibility`, `Project.is_draft`,
  `Project.published_at`, and `ProjectContentHead.published_release_id`
  untouched.
- Added project-scoped publication idempotency key/request hashes. Existing
  Releases remain valid with null values; same-key/same-request replay returns
  the original Release and same-key/different-request returns a conflict.
- Deliberately rejected a second publish while an active Release exists.
  Atomic supersede behavior is the next item, R5.3.

## Coupling Audit

- **R5.1 readiness:** R5.2 consumes the canonical snapshot and never rebuilds
  path selection from display indexes.
- **Concurrency:** publication locks first serialize Release pointer changes;
  Project/Head/source locks then prevent metadata, path promotion, Head moves,
  resource-slot changes, VoiceLine insertion or edits, and storage soft deletion
  from crossing the final fingerprint read.
- **Manifest and storage:** each graph UUID/hash is paired with its exact binding
  manifest. Storage IDs are explicitly present for media authorization and
  garbage-collection guards.
- **Release lifecycle:** this item creates only a first active published
  Release. It does not mutate an existing Release status; R5.3 owns supersede.
- **Public reads:** no public query changes here. R5.4 makes
  ProjectPublication the only public-read authority.
- **Routes:** the target `/publish` route is registered in R6.2. Existing Release
  routes remain untouched until their planned removal.
