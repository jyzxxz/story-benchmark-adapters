# R8.4 Validation - UUID-only Story Artifact Identity

## Scope

- Audited the replacement Outline, Chapter, CandidateSet, Script, VNGraph, and
  publication-readiness dependency graph.
- Removed the remaining sequence-based Branch, Script, and VNGraph Router
  modules after R8.3 froze their absence from the runtime contract.
- Split modern Bible, chapter-batch, and branch-generation services away from
  mixed compatibility modules so replacement Routers and Workers have an
  explicit UUID-only dependency boundary.
- Added an AST architecture gate and branch-equivalence regressions that fail
  when a modern module accepts or queries by `chapter_index`.

## Identity Audit

| Artifact | Identity used by active StoryPath code | Display-only data |
| --- | --- | --- |
| Outline | `story_path_id`, `outline_revision_id`, `story_path_chapter_id` | `display_index`; provider `chapter_index` is converted before persistence |
| Chapter | `path_chapter_id`, `chapter_slot_id`, `chapter_revision_id`, frozen context hash | denormalized legacy column and provider prompt fields |
| CandidateSet | `story_path_id`, `checkpoint_node_id`, `chapter_revision_id`, `state_snapshot_id`, `candidate_set_revision_id` | provider outline position |
| Script | exact `chapter_revision_id`, `script_revision_id`, and `path_chapter_id` | compatibility columns and prompt fields |
| VNGraph | exact `script_revision_id`, `chapter_revision_id`, resource-version IDs, and VNGraph revision ID | `display_index` in graph output and compatibility columns |

Generated Outline content is bound only to PathChapter UUIDs frozen in the
task source. A provider-returned index is not used as a lookup key. During
Outline activation, a row without `story_path_chapter_id` creates a new
ChapterSlot/PathChapter; it cannot silently reuse the current occupant of the
same display position. Reattaching or reordering an existing logical chapter
therefore requires its explicit UUID.

Chapter and CandidateSet workers now reject pre-StoryPath task snapshots before
calling a provider. Script source loading requires the ChapterRevision's frozen
PathChapter and exact OutlineChapter UUID. Script Head history is owned by
`chapter_revision_id`, and keyframe logical keys include the exact Chapter
Revision UUID instead of a chapter number.

VNGraph Head and revision history are owned by `script_revision_id`. New task
snapshots use `vngraph-binding-v2`, whose exact Revision and resource references
are identity and whose `display_index` is presentation metadata. Publication
readiness can still read persisted v1 manifests, but all newly queued compile
tasks must use v2.

## Dependency Boundary

The replacement Routers and Workers import:

- `story_bible_service` instead of the mixed revision service;
- `story_chapter_batch_service` instead of the sequence batch service; and
- `story_branch_contract` instead of the old branch persistence service.

The architecture test rejects imports of those mixed services, deleted Router
modules, and `legacy_chapter_script_queries` from every modern identity module.
It also rejects a `chapter_index` function parameter or SQLAlchemy query in the
replacement dependency graph.

The preserved pre-StoryPath server-agent workflow remains outside this graph.
Its sequence lookup is isolated in `legacy_chapter_script_queries`; after that
adapter resolves one Script revision, resource rendering receives the exact
`script_revision_id`. This boundary is covered by the server-agent regression
suite and cannot be imported back into modern authoring code.

## Removed Compatibility Tests

Tests that mounted deleted Routers or asserted removed `force_new` and split
Release behavior were deleted with their subjects. Their replacement behavior
is covered by CandidateSet review/promotion tests, optimistic Head tests,
atomic publication tests, public Release tests, and the R8.3 route-removal
matrix.

Legacy queued Outline, Chapter, CandidateSet, and VNGraph tasks are deliberately
not upgraded at worker runtime. Deployment must stop old producers and drain
those queues before switching the backend and workers. R8.5 records the exact
operational gate and rollback procedure.
