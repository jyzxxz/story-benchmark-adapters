# R4.1 Validation - Script Revisions Bound To Chapter Revisions

## Scope

- Changed ChapterScriptRevision numbering and history ownership from
  `(project_id, chapter_index)` to the exact `chapter_revision_id`.
- Added migration `0031_chapter_script_revision_heads`. It backfills legacy
  Script Head source IDs, makes the source required, permits an empty current
  pointer, and replaces the legacy revision constraint and lookup index.
- Added exact generation, revision-history, Head-read, and optimistic Head
  activation application services. The old index-based queue function is now
  an explicit adapter that resolves the supplied ChapterRevision UUID first.
- Frozen ChapterRevision, PathChapter provenance, BibleRevision,
  OutlineRevision, OutlineChapter, all relevant hashes, provider input,
  generation parameters, and editorial parent into each durable task.
- Removed source-hash global deduplication. Distinct idempotency keys can create
  multiple Script review candidates from one immutable ChapterRevision, while
  an exact key replay returns its original task.
- Changed successful provider output to a `ready` ChapterScriptRevision and
  stopped automatic Head movement. The empty Head remains at version 1 until a
  reviewer explicitly selects a revision with compare-and-swap.
- Kept `chapter_index` only as provider and rollback presentation metadata.
  Exact modern source loading uses the frozen PathChapter and OutlineChapter
  UUIDs and remains independent from later path reordering.

## Coupling Audit

- **StoryPath and Chapter:** the immutable ChapterRevision UUID is the Script
  family identity. PathChapter and display order are provenance and
  presentation fields, not lookup keys.
- **Outline:** modern tasks bind the exact OutlineChapter UUID for the frozen
  ChapterRevision context. The pre-StoryPath index lookup exists only in an
  explicit historical-data fallback.
- **Version control:** source equality is provenance, not deduplication.
  Multiple generation tasks produce separate immutable revisions; the Head is
  the sole review selection.
- **Branches:** sibling paths with equal display indexes receive independent
  ChapterRevision families, Script revision counters, and Script Heads.
- **Tasks:** the complete source envelope is checked before provider billing
  and before persistence. A task never consults a mutable Head after enqueue.
- **Resources and VNGraph:** resource slots continue to bind the exact
  ChapterScriptRevision. VNGraph compilation is addressed separately in
  R4.2-R4.4 and must consume only the selected exact Script revision.
- **HTTP:** target Script routes are already frozen in OpenAPI. Router
  registration and deletion of the old chapter-index prefix remain R6 and R8.
