# R7.2 Validation - Immutable Artifact Relation Backfill

## Scope

- Added Alembic revision `0037_backfill_immutable_artifact_relations` after
  the root-path backfill.
- Bound every legacy OutlineRevision to its project's root StoryPath and every
  OutlineRevisionChapter to the exact root PathChapter at its frozen display
  position.
- Copied the exact legacy project Outline Head UUID into the root
  StoryPathOutlineHead without borrowing the aggregate lock version.
- Converted unbound legacy candidates into CandidateSet bridge revisions tied
  to an exact root StoryPath, checkpoint, ChapterRevision, and StateSnapshot.
- Ensured every ChapterRevision owns one discoverable Script Head and every
  ChapterScriptRevision owns one discoverable VNGraph Head.
- Validated existing Script and VNGraph revisions and selected Heads against
  their exact immutable source UUIDs.

## Outline Backfill

Outline identity is moved in two steps: the revision receives `story_path_id`,
then each frozen outline row receives `story_path_chapter_id`. The legacy index
is consulted only inside this migration to locate the placement created by
R7.1. Runtime reads continue through UUID relations.

The migration rejects revision-number/content collisions, cross-path parent
revisions, missing root placements, and existing row bindings that point to a
different path. The selected Outline Revision ID is preserved exactly. The new
Outline Head keeps its own lock version rather than copying the old
ProjectContentHead cursor.

## Candidate Bridge

Legacy candidates are grouped by checkpoint only when the checkpoint records
an exact `content_revision_id` belonging to the root StoryPath. Candidate
groups outside the supported 2-4 size or without an exact source abort the
migration.

When the source ChapterRevision has no StateSnapshot, the migration uses a
content-addressed, project-scoped empty snapshot to represent the explicitly
unknown legacy base state. It never infers state from an index or mutable Head.

Bridge CandidateSet revisions intentionally have null `candidates_json` and
`content_hash`, and their CandidateSet Heads remain unselected. They are
discoverable for audit and provenance but cannot be activated or promoted as
reviewed target CandidateSets. Existing candidate rows, option keys, deltas,
preview references, statuses, and probabilities remain unchanged.

## Script And VNGraph

- ScriptRevision provenance must match its exact ChapterRevision project,
  frozen display metadata, BibleRevision, and OutlineRevision.
- Existing Script Heads must select a Script from the same ChapterRevision.
- VNGraphRevision provenance must match its exact ScriptRevision, including
  project and ChapterRevision.
- Existing VNGraph Heads must select a graph from the same ScriptRevision.
- Missing Heads are created empty at lock version 1. Existing selected Head
  UUIDs and lock versions are never replaced.

These empty Heads preserve the review rule: historical revisions become
visible, but R7.2 does not invent a review selection.

## Reversibility

Five `_alembic_0037_*` scratch tables record created rows and previous bridge
values. Downgrade removes only new CandidateSet/StateSnapshot/Head rows,
restores candidate and Outline relations, restores the root Outline Head, and
drops every R7.2 scratch table. A second upgrade produces the same UUIDv5 IDs.
