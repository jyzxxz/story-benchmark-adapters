# R5.5 Validation - Separate Authoring and Publication State

## Scope

- Added a read-only Project state projection service with independent
  `authoring` and `publication` results.
- Derived authoring blockers and the current fingerprint from the R5.1
  publication-readiness calculator instead of legacy workflow fields.
- Classified the earliest blocked authoring layer as Bible, StoryPath, Outline,
  Chapter, Script, or VNGraph, with explicit `ready` and forward-compatible
  `blocked` states.
- Counted only project-scoped queued and running GenerationTasks; partial tasks
  remain terminal.
- Derived `unpublished`, `published`, and `changes_pending` exclusively from
  ProjectPublication and the active Release fingerprint.
- Returned ProjectPublication `lock_version` in the publication projection so
  clients can satisfy the unpublish `If-Match` precondition. A project without
  a row receives logical initial version 1 without creating a database row.
- Rejected an invalid active pointer, damaged Release manifest, or malformed
  authoring fingerprint instead of falling back to Project lifecycle columns.

## Contract Clarification

The frozen OpenAPI contract already required `If-Match` for unpublish but did
not expose the corresponding ProjectPublication version. R5.5 makes
`publication.lock_version` required and constrains `authoring.stage` to the
implemented stable values. This is additive response data and is required for
the existing unpublish operation to be usable without an out-of-band query.

- a ready but never-published project is `unpublished` and has unpublished
  authoring state;
- first publish is `published`, an authoring edit is `changes_pending`, and
  reverting the edit restores `published` without creating a Release;
- unpublish returns to `unpublished` and exposes the incremented lock version;

- corrupt active Release state returns a stable conflict;
- unknown future blocker codes cannot incorrectly project as ready.

## Coupling Audit

- **Readiness:** the projection consumes the exact canonical fingerprint and
  blocker set; it does not implement a second authoring completeness model.
- **ProjectPublication:** pointer, timestamp, and lock version are the only
  publication-state source.
- **ProjectRelease:** lifecycle, manifest hash, and frozen fingerprint are
  validated before comparison with current authoring.
- **GenerationTask:** only nonterminal project-scoped rows affect the activity
  count; task stage strings never replace the domain authoring stage.
- **Legacy fields:** Project status, visibility, draft flag, publication time,
  and ProjectContentHead lifecycle status are neither read nor written.
- **API:** R5.5 implements the projection and clarifies its schema; R6.1 binds it
  to the replacement Project router.
