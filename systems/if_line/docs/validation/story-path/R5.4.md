# R5.4 Validation - Active Release Public Reads

## Scope

- Added an atomic unpublish command guarded by the ProjectPublication
  `lock_version` supplied through `If-Match`.
- Withdrew only the current active Release, cleared the publication pointer,
  and incremented the lock without changing legacy Project publication fields.
- Added public read selectors for the project catalog, active project Release,
  Release manifest, PathChapter manifest, and VNGraph snapshot.
- Required every public selector to join through
  `ProjectPublication.active_release_id`; Release status alone cannot make a
  row public.
- Verified Release manifest hashes and exact frozen VNGraph provenance before
  returning data.
- Changed anonymous media authorization to require an intact active Release
  whose top-level `storage_object_ids` contains the exact object UUID.
- Kept sensitive private namespaces unavailable even when listed, and allowed
  non-sensitive shared StorageObjects with a null `project_id`.

Expected coverage:

- active Release catalog, project, manifest, PathChapter UUID, and VNGraph
  reads succeed from frozen data;
- a non-active row remains hidden even if its status is manually set back to
  `published`;
- successful unpublish withdraws the Release, clears the pointer, increments
  the lock, and immediately revokes public data and media access;
- stale and invalid preconditions make no state change;
- an injected failure after flush rolls back Release status, pointer, timestamp,
  and lock version;
- manifest corruption, incidental UUID text, and sensitive namespaces cannot
  authorize media;
- shared resources with `project_id = NULL` can be authorized by an exact active
  manifest reference.

## Coupling Audit

- **ProjectPublication:** remains the sole public-state authority for project,
  Release, graph, and media reads.
- **ProjectRelease:** public reads verify both lifecycle state and immutable
  manifest hash; superseded history remains owner-visible but never public.
- **StoryPath:** public chapter lookup uses frozen `path_chapter_id`; no
  `(project_id, chapter_index)` selection is reintroduced.
- **VNGraph:** the frozen graph, ChapterRevision, ScriptRevision, binding
  manifest, and hashes must still agree with the immutable VNGraphRevision.
- **Storage:** public authorization consumes only the canonical Release resource
  list and does not mutate StorageObject visibility during publish or unpublish.
- **Legacy APIs:** no router is switched in R5.4. R6.2 will bind the frozen
  OpenAPI routes to these services, and R8 removes the old release endpoints.
