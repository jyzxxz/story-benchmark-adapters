# R2.5 Validation - Optimistic Revision Head Activation

## Scope

- Added strict integer `If-Match` parsing. Positive unquoted and quoted lock
  versions are accepted; missing, weak, list, zero, negative, and mismatched
  quote forms are rejected.
- Added conditional SQL compare-and-swap for Project Bible Heads and
  StoryPathChapter Heads. The update predicate includes the caller's expected
  `lock_version`; a successful pointer change increments the version exactly
  once.
- Added StoryPath Outline Head activation with the same CAS inside the
  transaction that reconciles stable PathChapter topology. A stale token is
  rejected before topology changes and a racing update is rejected by the SQL
  predicate.
- Standardized `409 head.version_conflict` with the current Head envelope in
  error details so clients can refresh without a second blind write.
- Defined matching re-selection as a verified no-op: it requires a current
  token and does not increment `lock_version` or alter `updated_at`.
- Made `StoryPathOutlineHead.current_revision_id` nullable and added migration
  `0027_nullable_outline_head`. An empty Head starts at version 1, so the first
  selection does not borrow `StoryPath.lock_version` or require a special API.
- Updated the target OpenAPI and architecture documents to expose an empty Head
  as `{revision_id: null, lock_version: 1}`.
- Kept explicit legacy activation wrappers only for routes scheduled for
  deletion in R8. Target routers in R6 call the strict expected-version entry
  points.

## Concurrency And Coupling Audit

- **Bible:** target selection updates only `current_bible_revision_id`,
  `lock_version`, and `updated_at`. The legacy project workflow status remains
  confined to the temporary old-route wrapper.
- **Outline:** Head CAS and chapter topology reconciliation share one database
  transaction. Any validation error or failed CAS rolls back both.
- **Chapter:** ownership is `PathChapter -> ChapterSlot -> ChapterRevision`.
  `chapter_index` is not used to find or authorize a target Revision.
- **Generation:** activation does not mutate Revision status and generation
  still never moves a Head.
- **Context:** an existing empty Outline Head is treated exactly like no
  selected Outline; a null Revision ID cannot enter a frozen generation
  manifest.
- **Branching:** inherited prefixes may select a Revision from a shared
  ChapterSlot; divergent sibling slots cannot cross-select Revisions.
- **HTTP:** strict Head services and schemas are complete. Route registration
  and owner checks remain R6.1; old action routes remain until R8.1.
- **Migration:** downgrade removes only empty Outline Head rows before restoring
  the old non-null constraint. Selected pointers are preserved.
