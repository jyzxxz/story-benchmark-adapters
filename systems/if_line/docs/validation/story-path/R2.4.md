# R2.4 Validation - Frozen StoryPath Chapter Generation

## Scope

- Added a PathChapter application service that freezes the exact StoryPath,
  ChapterSlot, editorial parent Revision, Bible Revision, Outline Revision,
  StateSnapshot, predecessor Revision chain, and provider parameters before a
  task is queued.
- Added a hashed `story-path-chapter-source-v1` task envelope. Workers validate
  both the envelope hash and the canonical `StoryContextResolver` hash before
  calling a provider and again before finalization.
- Replaced project-wide predecessor discovery with ordered Revision IDs from
  the frozen predecessor manifest. `display_index` is passed to the legacy LLM
  adapter only as presentation metadata.
- Persisted generated prose in the target ChapterSlot as a `ready`, immutable,
  unselected ChapterRevision. Generation never changes StoryPathChapter Head,
  legacy ChapterHead, or project workflow state.
- Added PathChapter batch orchestration. Every child freezes its own context at
  enqueue time; a batch is rejected before task creation when a requested
  chapter has an unreviewed predecessor.
- Made same-key retries return the original frozen single or batch Task even
  when mutable Heads changed after the first request.
- Preserved execution and recovery of tasks queued with the legacy source
  schema. They no longer discover predecessor prose dynamically and their
  results are review-only.
- Removed every active chapter-generation query shaped as
  `chapter_index < target`, including the old service and AutoCreator paths.
  AutoCreator now uses only prose generated earlier in its current ordered run.

## Coupling Audit

- **Outline:** task validation reloads the exact StoryPath Outline Revision and
  its target `story_path_chapter_id`; it never follows the mutable Outline Head.
- **Revision review:** generation stores the target Head at enqueue only as
  `parent_revision_id`. It does not select the generated Revision. Optimistic
  Head activation remains R2.5.
- **Branching:** predecessor IDs are resolved only inside the target StoryPath.
  Parent and sibling Head changes cannot enter a frozen child task.
- **Batching:** child dependencies control execution order only. They do not
  make an unreviewed generated child the context of another child.
- **Script and VNGraph:** downstream artifacts can bind the exact generated
  ChapterRevision ID. Their Head and compiler changes remain R4.
- **HTTP:** the target single and batch task builders are complete, but their
  UUID routes remain assigned to R6.1. Existing routes stay registered until
  the atomic R8 cutover.
- **Legacy boundary:** old tasks without an explicit predecessor Revision list
  run with empty predecessor context. This intentionally avoids cross-branch
  leakage until those index-based routes are removed.
