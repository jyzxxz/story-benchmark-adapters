# R8.5 Validation - Migration Cutover and Operations

## Scope

- Added an executable cutover audit for the exact Alembic head, active
  StoryPath authoring tasks, and open task Outbox events.
- Added a retry boundary that retains terminal legacy tasks for audit but
  rejects their retry before quota reservation, task mutation, or Outbox write.
- Extended the migration verifier test into a disposable
  `0035 -> 0038 -> 0035 -> 0038` rollback round trip.
- Added the deployment, backup, smoke, observation, and backup-restoration
  runbook with an authoritative port map.
- Synchronized the API replacement matrix, architecture, image resource flow,
  systemd instructions, and TTS launcher with the final cutover state.

No live production database, Redis instance, reverse proxy, or systemd service
was changed during this item. Production execution remains an operator action
governed by `docs/operations/story-path-cutover-runbook.md`.

## Cutover Contract

The gate covers these task kinds:

```text
outline.generate
chapter.generate
chapter.batch
branch.candidates.generate
chapter_script.generate
vngraph.compile
```

Queued/running tasks and pending/publishing/failed Outbox events block cutover.
Terminal legacy-source tasks produce a warning. Their retry returns HTTP 409
without reopening the usage reservation or adding another Outbox event. Tests
bind each gate schema version to the version constant used by its authoring
service so the audit cannot silently drift from task producers.

## Rollback Rehearsal

`test_story_path_release_backfill_verification.py` now performs:

1. upgrade a disposable SQLite database to 0035 and seed representative legacy
   Heads, Script/VNGraph relations, CandidateSets, and active Releases;
2. capture the privacy-preserving baseline;
3. upgrade to 0038 and verify exact rows, Heads, manifests, and public access;
4. downgrade to 0035 and require the new snapshot hash to equal the original;
5. upgrade to 0038 again and rerun the verifier;
6. corrupt Head and Release data and prove the verifier detects the damage.

Production rollback deliberately uses the pre-cutover PostgreSQL and Redis
backups plus the previous backend/frontend artifact. The disposable downgrade
test is not presented as a substitute for production backup restoration.

## Identity Review

The new runtime module inspects only task kind and frozen schema/manifest
versions. It does not accept, query, or join `chapter_index` or `display_index`.
The cutover script queries task and Outbox identity by task UUID. Documentation
uses chapter sequence only when naming removed legacy routes or explaining the
migration source.
