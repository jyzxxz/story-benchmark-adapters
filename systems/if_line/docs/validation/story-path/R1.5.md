The new table accepts an explicit unpublished state and constrains active
Releases to the same project through a composite foreign key. The pointer and
activation timestamp must be both null or both present, and optimistic locking
starts at a positive version. Release status is now limited to `published`,
`superseded`, and `withdrawn`.

Migration 0026 preserves legacy draft IDs in a reversible migration snapshot,
maps those rows to `withdrawn`, and restores their exact status and withdrawal
timestamp on downgrade. `authoring_fingerprint` and `release_notes` are nullable
bridges until the R5 publication service and R7 backfill make them authoritative.
The migration deliberately leaves `ProjectPublication` empty; R7.3 will derive
the one active pointer from legacy public state.

The historical 0007 Release table and 0020 Script Head backfill are insulated
from current ORM metadata so populated databases can traverse the complete
migration chain. The three broader-suite failures are frozen legacy contract
assertions: one expects `publish: false` to create a draft Release and two expect
the removed `is_draft` response field. They are assigned to R5/R5.5 and do not
indicate a schema failure. Two unrelated runtime checks remain environment
sensitive: metrics expects a configured task database and readiness expects a
Redis check despite the effective test settings.
