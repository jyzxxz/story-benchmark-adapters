# R3.3 Validation - Candidate Promotion Into A Child StoryPath

## Scope

- Added a transactional promotion service for one candidate from the active,
  reviewed CandidateSet Head. Promotion rejects candidates from stale or
  inactive sets and revalidates the exact checkpoint ChapterRevision and
  StateSnapshot used to generate the set.
- Created one child StoryPath with immutable fork provenance pointing to the
  parent path, fork PathChapter, checkpoint, and selected candidate. Promotion
  does not create a BranchEdge or mutate the candidate set.
- Copied the parent's exact reviewed predecessor chain through the fork chapter
  into child StoryPathChapter placements. The copied rows share ChapterSlots
  and immutable ChapterRevisions while retaining child-local placement IDs,
  predecessor links, and future Heads.
- Applied the candidate state delta as a bounded JSON merge into a
  content-addressed StateSnapshot. Object values merge recursively and null
  deletes a key. The child path points to the resulting snapshot.
- Added an empty child StoryPath Outline Head so the branch can receive a new,
  reviewable outline without inheriting the mutable parent Outline Head.
- Added immutable StoryPathPromotionRecord rows keyed by
  `(user_id, idempotency_key)`. Exact retries return the same child path;
  conflicting key reuse is rejected; a candidate cannot create a second path.
- Wrapped snapshot, path, shared-prefix, Outline Head, and idempotency writes in
  a database savepoint. A failure at any point removes all partial writes even
  when the caller catches the error before committing its outer transaction.
- Locked the user command scope, source path/checkpoint/chapter placement,
  CandidateSet Head, and shared-prefix rows while promoting to prevent Head
  changes between validation and copy.
- Added migration `0030_story_path_promotions`, response/request schemas, and
  schema fingerprint, constraint, index, and foreign-key checks.
- Froze the selected candidate preview and state delta in StoryContext. Chapter
  generation after the fork receives the branch choice after the shared parent
  chapters; previously frozen manifests without this field remain replayable.

## Coupling Audit

- **Candidate review:** promotion consumes only the CandidateSetRevision chosen
  by the exact path/checkpoint CandidateSet Head. It does not move that Head.
- **Chapter identity:** source and prefix ownership use PathChapter,
  ChapterSlot, and ChapterRevision UUIDs. `display_index` only verifies and
  reproduces order; `chapter_index` remains provider presentation metadata.
- **Outline:** the child receives a null Outline Head and cannot accidentally
  resolve the parent's mutable outline. A later child outline reuses inherited
  PathChapter IDs and creates new post-fork ChapterSlots.
- **Chapter generation:** the immutable selected candidate is part of the
  context manifest and is included only when generating a chapter after its
  fork position.
- **State:** the candidate's frozen source StateSnapshot is validated before
  its delta is applied; no mutable project-level state is consulted.
- **Script and VNGraph:** inherited ChapterRevision IDs remain valid exact
  inputs. Child post-fork revisions will receive independent script and graph
  Heads in R4.
- **Publication:** promotion changes authoring state only. No Release or public
  pointer is created or updated.
- **HTTP:** application services and schemas are ready; route registration and
  owner-scoped transport mapping remain R6.
- **Migration:** the new table is additive and records synchronous command
  idempotency. Historical candidate/path relation backfill remains R7.2.
