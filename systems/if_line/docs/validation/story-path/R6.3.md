# R6.3 Validation - Path-Based Frontend API Client

## Scope

- Added a typed frontend client for all 58 operations in the frozen StoryPath
  authoring contract.
- Added response and request types for Project projections, immutable artifact
  revisions, StoryPath branches, path chapters, Candidate sets, resource slots,
  VNGraph revisions, Releases, and public Release snapshots.
- Kept the Axios `/api` base client and security interceptors as the single HTTP
  transport. Route builders therefore contain the contract path below `/api`
  and do not create a second transport stack.
- Kept numeric Project IDs because they remain the Project aggregate identity.
  Every Outline, path chapter, ChapterRevision, Candidate, ScriptRevision,
  ResourceSlot, VNGraphRevision, and Release reference uses a stable UUID.
- Added the API contract tests to the existing frontend unit-test command.

This checkpoint introduces the complete replacement client without switching
the current authoring and publication views. R6.4 performs the StoryPath and
Revision-review UI cutover, R6.5 performs the atomic publication UI cutover,
and R8.2 deletes the then-unused index-based client modules. The R6 checkpoints
are deployed as one release unit.

## Request Semantics

- All 11 durable generation, promotion, rendering, compilation, and publish
  commands require `Idempotency-Key`. The helper rejects empty or overlong
  caller keys and generated keys retain their random suffix even with a long
  scope.
- Bible, Outline, Chapter, CandidateSet, Script, and VNGraph Head changes send
  `If-Match`. StoryPath updates, path-chapter appends, resource binding, and
  unpublish use the same lock precondition.
- Public VNGraph reads accept an optional ETag, send `If-None-Match`, and treat
  both 200 and 304 as valid Axios responses.
- Route segments are encoded before interpolation so an identifier cannot alter
  the endpoint hierarchy.

## Coupling Audit

- **Project and Bible:** Project reads expose authoring and publication
  projections. Bible history and Head selection are independent of StoryPath
  branch creation.
- **StoryPath and Outline:** a Candidate promotion creates a StoryPath; editing
  an Outline revision or changing its Head never creates a branch.
- **Chapters:** chapter order is represented only by `display_index`. Generation
  and revision calls use `story_path_id`, `path_chapter_id`, or
  `chapter_revision_id` according to the backend ownership boundary.
- **Candidate branches:** CandidateSet retry/review calls remain attached to a
  StoryPath checkpoint. Only explicit Candidate promotion calls a StoryPath
  creation endpoint.
- **Script, resources, and VNGraph:** Script generation starts from an exact
  ChapterRevision. Resource and VNGraph calls start from an exact
  ChapterScriptRevision, and direct graph reads use a VNGraphRevision UUID.
- **Publication:** owner publish/unpublish and Release history are separate from
  immutable public manifest and graph reads. No public request reads live
  authoring state.
