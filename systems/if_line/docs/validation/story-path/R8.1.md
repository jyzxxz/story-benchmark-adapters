# R8.1 Validation - Legacy Authoring Router Removal

## Scope

- Removed the remaining legacy authoring Router imports and registrations from
  `app.main.create_app`.
- Regenerated the complete `backend/openapi.v2.json` runtime contract.
- Updated the existing route ownership test to require UUID-keyed VNGraph and
  Project metrics routes.
- Retained legacy Router source modules for the explicit removal-contract audit
  in R8.3; they are no longer reachable through the production application.

## Removed Runtime Routers

The following early-v2 compatibility Routers are no longer imported or mounted
by the application factory:

| Router module | Removed contract family |
| --- | --- |
| `app.routers.v2.revisions` | project-wide Bible/Outline/Chapter Heads, generation, readiness, and stats |
| `app.routers.v2.branch_generation` | project-scoped unversioned branch candidates |
| `app.routers.v2.chapter_scripts` | project plus `chapter_index` Script routes |
| `app.routers.v2.vn_graphs` | project plus `chapter_index` VNGraph routes |

The older Project Router had already been unregistered by R6.1. The split
legacy Release owner/public Routers had already been unregistered by R6.2 when
the atomic publication Router replaced them. R8.1 verifies the effective
runtime registration set rather than introducing duplicate removals.

## Preserved Routers

The application still mounts:

- the path-aware Project, Bible, StoryPath, Outline, Chapter, Candidate,
  Script, VNGraph, and atomic Release Routers;
- stable ID-based Task, Asset, VoiceLine, Media, ReadingSession, continuation,
  and visual asset APIs; and
- authentication, provider, social, TTS, image generation, server agent, and
  voice clone infrastructure outside this authoring cutover.

No Router source was deleted in this commit. Direct unit tests for legacy
service behavior remain usable until R8.3 finishes the removal contract, but
importing `app.main` cannot expose those endpoints.

## OpenAPI Delta

The deterministic runtime OpenAPI snapshot changed from 137 paths to 109. All
28 removed paths belong to the four unregistered compatibility Routers. The
delta added no path.

Removed families include:

- `/api/projects/{project_id}/bible/*` and `/outline/*`;
- `/api/projects/{project_id}/chapters/{chapter_index}/*`;
- `/api/projects/{project_id}/branch-candidate-generations` and old checkpoint
  candidate reads;
- `/api/projects/{project_id}/chapter-generation-batches`;
- `/api/projects/{project_id}/readiness`; and
- `/api/projects/{project_id}/stats*`.

The replacement Project metric paths are
`/api/projects/{project_id}/metrics` and
`/api/projects/{project_id}/metrics/artifacts`.

## Chapter Identity Review

`app.main` no longer imports any Router whose resource identity contains
`chapter_index`. The retained runtime VNGraph endpoints are keyed by
`script_revision_id` and `vn_graph_revision_id`. The retained Chapter endpoints
are keyed by `story_path_id`, `path_chapter_id`, or `chapter_revision_id`.

The old module files still mention `chapter_index`, but they are unregistered
test/migration evidence, not active application routes. R8.4 performs the final
active-code architecture scan after frontend cleanup.
