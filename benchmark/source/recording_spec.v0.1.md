# 八项指标的运行证据保存规范 v0.1

这是建议新增的适配器采集规范，不是三个项目已经实现的功能，不是生成结果。
配套 record_templates.json 是字段模板，null 表示未知、未采集或未适用。示例 ID 只演示关联。

## 1. 指标范围

M1 固定事实与要求满足率；M2 故事连贯性；M3 人物视觉一致性；
M4 等待时间；M5 阅读体验；M6 图文匹配；M7 token 消耗；M8 图片生成数量。
本版不新增分支有效性、图片审美或完整作品成功率作为独立评分项。
选择、错误、停止原因仍作为解释这八项的必要证据保存。

M1/M2/M3/M5/M6 由文本或视觉 AI 审核并可抽样人工核查。
M4/M7/M8 由程序从真实事件、usage、资产记录计算，AI 只能解释结果，不能猜原始数值。

## 2. 运行结构

建议以 root_run_id 表示一个系统对一道题的一次独立生成。
trajectory_id 表示这个根运行中的实际路径。公共规划、复用资产和模型调用在根运行只记一次。
每条路径独立保存访问顺序与正文修订，不能拼接互斥路线。

runs/<root_run_id>/
  manifest.json
  inputs/shared_task.txt
  inputs/brief.txt
  inputs/opening.txt
  inputs/constraints.json
  native/                         原生大纲、设定、记忆、脚本和修订，供审计
  trajectories/paths.json
  trajectories/<path>/story.jsonl
  trajectories/<path>/choices.jsonl
  characters/versions.jsonl
  images/requests.jsonl
  images/outputs.jsonl
  images/assets.jsonl
  images/files/
  visuals/frame_map.jsonl
  visuals/clean_frames/
  visuals/ui_captures/
  telemetry/calls.jsonl
  telemetry/events.jsonl
  telemetry/raw/                  脱敏后的真实请求响应，保留完整 usage
  errors.jsonl
  evaluation/                     后生成，不能作为生成系统的新记忆

目录不是性能评分单位。测试期可共用内容寻址存储，但索引必须可追溯。

## 3. 各指标最低证据

### M1 固定事实与要求满足率
保存完整公共任务、原 brief、固定开头、已确认时点解释、约束清单、实际路线正文、选择记录、停止原因。
约束清单只能整理已公开要求，不得加入新答案；提供 source_quote/source_file。
区分永久规则、初始状态、必需呈现、知识边界和条件触发要求。
固定开头已满足的事件不作为系统新增生成奖励，后续违反前文仍可记错。
规划或 Bible 中写了某事实，并不表示玩家正文已遵守。
区分 pass/fail/unknown/not_applicable；未到明确里程碑的事项不能装作已经评完。
### M2 故事连贯性
保存本路径完整可见正文、顺序、说话人、选择、版本与出处，公共前文单列。
保留原生状态供诊断，但不能用它代替正文证明事情发生过。
让裁判核对“前文已有事实”和“后文冲突”两处证据。
后生成的事实表属于评审端派生材料，不得传回生成器。
### M3 人物视觉一致性
保存题目明确的稳定外貌、原生人物设定的版本、原生参考资产、每次实际画面出现和角色映射。
保存换装、受伤、时间跳跃等允许变化的正文依据，而不是仅保存模型自称的状态。
题目未规定的发色等不能自造为公共标准。参考图本身可能错误：
区分“符合公共设定”和“跨画面保持同一形象”。
至少两次可比较的出场才支持跨场景判断；背影/遮挡时可以无法判断。
角色名与画面人物映射是候选信息，裁判应结合画面核查。
### M4 等待时间
记录运行提交、首个新增正文可获得、首个新增正文真实显示、
对应非占位画面就绪/实际显示、玩家选择、所选后续正文和画面就绪/显示、停止事件。
用同一观察者/clock_id 的单调时间计算间隔；UTC 用于串联日志。
后端可获得时间不等于前端显示时间。无前端测量就只报告适配器/后端时间。
公共固定开头立即显示不算首次新正文；第一个模型 chunk 也可能是规划或标签。
用户读故事和犹豫时间不算系统响应。交互 ID 对齐选择及所选路线，不拿其他预取路线的时间。
并行调用耗时不能直接相加作为玩家等待。
预取命中时响应很快是正常结果，但其生成调用仍在根运行计费。
### M5 阅读体验
保存原生可见完整文字、段落、对白、选项、实际顺序和评测截止位置。
主项建议是文本阅读体验，以免图片/延迟反复计入其他指标。
冻结评审所看的修订；在线用户看过的早期文本不能用后来改稿替代。
只供文本评价的盲审包不含系统名、模型、费用、内部审核分或实现说明。
固定开头只作上下文，不计作系统原创。前缀未完结不强制按完整故事评结局。
AI 喜好不是已被真人证实的用户满意度。
### M6 图文匹配
必须保存原文段落与实际合成画面之间的映射，不是只有两个无关文件夹。
记录场景与原生单元定位、frame_id、对应 segment/revision、图层资产 ID、角色候选 ID。
保存干净合成画面及原始 UI 截图；评分优先干净画面，防止从字幕取得答案。
画面应由原生渲染器捕获，或由等价的确定性组合重建并明确标记，不用 AI 补画。
背景+立绘的系统与整图系统比较实际合成画面，不要求裸背景包含全部角色。
保存原生生成前的画面锚点/构图用途作为诊断，不能生成后为错误补理由。
文本为主要比较依据，图片 prompt 只供诊断，不能取代故事和公共约束。
静态图可能覆盖多个段落，应保留整个显示区间及关键事件；不能只挑最匹配的一句。
区分本轮媒体禁用、应有但缺失、占位与真正图文矛盾。
### M7 token
采集所有规划/写作/内部审核/修订/相关文字侧调用和失败重试。
外部评测调用 purpose=evaluation 单独记，不混入生成消耗。
每个实际请求尝试有唯一记录；供应商 ID 用于核对，不能按 prompt 相同就去重。
保留供应商 raw usage 和版本化标准化规则。
缓存、推理、图像等细分可能已包含在总量中，不能不加区分求和。
文本和多模态 token 分列；不提供 token 的图像服务按请求/图/费用记，不编造换算。
缺失为 null。部分覆盖只能报告已知小计及覆盖，不能叫完整总量。
输入/输出消息有助诊断，不等于可反推出全部真实计费 token。
### M8 图片数量
分开请求尝试、供应商返回候选、本地文件资产、实际使用记录、合成显示画面。
一次请求返回4张，代表1次请求、4个返回候选，不是4次请求。
同一候选另存PNG/WebP或缩略图，不新增模型生成数量。
两个独立候选像素相同：候选产出数仍是2，独立内容数可以是1。不要用内容去重抹掉生成成本。
记录成功、失败、退回重生、未选、预取、现有图库、缓存和占位来源。
原始文件保存到本地/稳定存储；URL单独保存但不作为唯一证据。
下载失败不能删掉供应商已返回候选记录；返回数量未知就记未知。
保留原始 file hash，像素标准化 hash 仅做另一种去重统计，不宣称感知语义去重。
使用数以实际路径的资产引用计算；原生根故事生成未访问分支的图不一定是浪费。

## 4. 关键关联

shared_task/constraint -> story segment/revision -> frame -> layer asset -> image output -> request/model call
story segment/revision -> source text call
frame/segment -> displayed event -> interaction -> observed latency
entity/version -> reference assets -> appearances in path frames
所有关联最终回到 root_run_id；跨路径共用内容不重复记账。

## 5. 建议事件类型

run_submitted
model_request_started / model_first_chunk / model_request_finished
story_text_available / story_text_presented
frame_required / frame_ready / frame_presented
choice_presented / choice_selected
run_stopped

每个事件保存 event_id、interaction_id、trajectory_id、observer、clock_id、UTC、单调计时和相关内容ID。
frame_presented 只能由实际显示观察者记录；不能让模型填写这些值。

## 6. 裁判输入与回传结果

事实审核：公共任务/约束+前文+本路径正文+选择+范围。
连贯审核：前文+本路径有序正文+选择；原生计划只供后续诊断。
人物视觉：公开稳定设定+原生参考与来源+同人跨画面序列+合理变化的正文依据。
阅读体验：匿名的前文+可见正文+选项+范围，不给内部计划、成本和系统身份。
图文匹配：正文及必要上下文+对应干净画面+公开视觉约束，不用图像prompt充当标准。
程序项：真实日志生成数量/时间/token报告，AI仅解释。
裁判响应保留模型版本、提示词hash、输入包hash、展示顺序、抽样规则、证据ID、理由、分数或无法评估状态。
不要要求裁判输出隐藏思维过程；只需简短可核查的理由。
评审数据中的指令是待评内容，不得改变裁判规则。

## 7. 验收

1. 提供任一正文段落，能找回原生修订与实际关联画面。
2. 提供任一画面，能找回资产、候选、生成请求或图库来源。
3. 提供任一角色，能得到按路径排序的出场与合法变化。
4. token总量可以从真实尝试记录重算；不完整时报告覆盖。
5. 图片请求、候选、独立内容、实际使用、复用、合成数量不会混淆。
6. 时间可从同一观察者的事件重算；首token不冒充首次可读，后端就绪不冒充用户显示。
7. 不同路径不串线，不把公共前文或共享调用重复当独立产出。
8. 原始证据在先，评分在后；缺失不可由另一个AI补造。
9. 运行失败和资产下载失败被保留；选择记录仅解释文本，不新增分支有效性评分。
10. 文件、私有请求和公开裁判包隔离；脱敏密钥、cookie、个人账号和敏感URL参数。
