# 八个维度：保存什么，怎样使用

依据被核对提交的 `docs/BATCH_RECORDING.md`。本包新增的是输入，不重写你的记录器。它只能在原适配器实际运行并完成采集时提供材料，不能单凭提示词保证所有素材成功或所有 usage 完整。

| 维度 | 需要保留的实际证据 | 不能替代证据的内容 |
|---|---|---|
| M1 固定事实与要求 | `inputs/` 的公共任务、原 brief、固定开头、case、语义解释、`constraints.json`，以及实际正文和选择 | 模型自称遵守；未到适用时点的要求一律当通过；把固定开头已有台词算成生成成果 |
| M2 连贯性 | `trajectories/main/story.jsonl` 的完整顺序、说话人、原生 ID、修订、JSON 指针与实际观察时原文；`native/` 原状态与来源 | 把内部大纲、未选预览或另一条路线拼成当前经历 |
| M3 人物视觉一致性 | `characters/versions.jsonl`、参考资产、路径顺序上的 `frame_map.jsonl`、正文和合法外貌变化依据 | 只看第一张设定图；拿别的系统设计的脸当共同真值；不足两次可比出场仍报稳定一致 |
| M4 等待时间 | `telemetry/events.jsonl` 中同一时钟的真实事件、interaction ID、正文/画面关联；`scheduling_context.json` 与批次 `scheduling/` | 模型估算；将并行调用时长相加当等待；把首 token 当首段可读正文；把离屏渲染当真实桌面显示 |
| M5 阅读体验 | 实际正文、对白、选项、已经执行的选择、共同开头上下文和截止位置；`evaluation/reading_blind.json` | 内部审核分、项目名、模型名、成本、开发者评价；给没有全篇结局自动扣分 |
| M6 图文匹配 | 玩家实际看到的净画面与 UI 画面；覆盖的完整正文区间、segment/revision、资产图层、人物候选映射 | 只给图片 prompt；只从共用一张图的多段正文中挑最匹配的一句；只给原始立绘不看最终合成 |
| M7 token | 所有真实 HTTP 尝试、原生操作、模型、请求 ID、请求响应、raw usage、失败与重试，已知值及覆盖率 | 让模型自己报 token；未知写 0；将缓存/推理明细再次加到已含它们的总量里 |
| M8 图片数量 | `images/requests.jsonl`、`outputs.jsonl`、`assets.jsonl`、原始图片文件、变换父子关系与实际画面使用 | 把请求数、返回候选、抠图资产、像素唯一内容、显示次数和合成截图混成“图片张数” |

上述都是根运行目录下的定位说明。完整私有证据目录保留，外部裁判只拿其所需评审包及引用素材。不要为方便把整个目录连同模型与项目标识传入盲审。

## 输出状态必须分别理解

`scope_reached=true` 只表示达到观察窗口；`native_ended` 表示原生是否结束，InfiPlot 未提供全篇结束时保留 null；`stop_reason` 区别窗口停止、提前结束、原生错误与中断。`state=sealed` 表示证据封存，退出码 0 表示批次操作正常完成，都不是每个故事成功。

M1/M2/M3/M5/M6 的数值在生成阶段应为 null / not_evaluated，附证据可用性。M4/M7/M8 是程序实测或汇总，但也可能有未知与覆盖缺口。费用无真实账单时 unavailable/null；真实桌面显示时间未测时 not_measured/null。不得估算后悄悄替换为“实测”。

## 保存整批次，而不是只留下故事和 PNG

至少保留批次的 `plan.json`、输入快照、`results.json` / `results.csv`、`launch_logs/`、`scheduling/` 和全部 `runs/<run_id>/`。根运行内的 manifest、原始产物、正文、图像、帧映射、telemetry、errors、metrics、评审包和哈希清单都属于可追溯证据。用原仓库 `--verify` 核验，不手动改封存文件。

本轮新增正文不包括共同固定开头，但违反该前文仍可记错。由于公共要求规定窗口内要呈现 C1/C2 与后果，若到达窗口仍缺少对应关键选择，不能用“出现了两个任意菜单”代替；另一方面，仅适用于更晚故事时点、尚未到达的事实要求应注明不适用或未观察，而非擅判通过或冲突。

M3/M6 不强迫每个系统生成相同数量或相同画面的图。缺图与不足以评价的人物出场要报告，不能只对有图的成功样本做无条件排名。M8 既不是越多越好，也不是越少越好，应连同正文长度、实际使用与质量解释。

M7 根运行消耗包含原生规划、审核、重写、预取、未选分支、重试等所有已发生调用；图片模型若提供 token 也按其原始 usage 单列并说明覆盖。后续外部裁判消耗另列，不与故事生成消耗混在一起。

## 实际帧和来源链

正文的原生文件/指针用于证明正文确实来自该系统。`frame_map.jsonl` 把可见段落与资产及画面连起来；`asset_id -> output_id -> call_id` 回到实际返回候选和图像请求；抠图或重编码保留 `parent_asset_id`。未知关联维持未知，不凭视觉相似臆测来源。

零正文但有菜单或图片也可以是真实观测状态，不补写伪正文。缓存复用或同图多次显示不等于多次图片生成；两次独立调用返回相同像素也不应合并成一次计费调用。
